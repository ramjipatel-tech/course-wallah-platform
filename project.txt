1. CORE ARCHITECTURE & SYSTEM OVERVIEW
================================================================================
The platform operates as a unified dual-engine application:

A. BACKEND API (FastAPI + Async SQLAlchemy):
   - Location: `api/`
   - Entry point: `api/server.py`
   - Framework: FastAPI with Uvicorn / Gunicorn
   - Database: SQLite / PostgreSQL via Async SQLAlchemy ORM (`db/`)
   - Core API Routes:
     * `/api/v1/apps` & `/api/apps`: Lists educational app hubs (Physics Wallah, Apna College, KGS, Technical Classes, etc.)
     * `/api/v1/batches` & `/api/batches`: Lists batches, subject hierarchies, and folders.
     * `/api/v1/lectures/{id}`: Lecture metadata and sibling video playlists.
     * `/api/v1/lectures/{id}/access`: Secure video playback resolver (returns direct stream URL without exposing bot credentials).
     * `/api/v1/stream/tg/{message_id}`: High-performance Telegram MTProto video proxy streaming direct MP4 chunks with HTTP 206 Byte-Range support.
     * `/api/v1/pdfs/{id}/content`: Secure PDF proxy streaming from Backblaze B2 or storage.

B. TELEGRAM BOT ENGINE (Pyrogram / Hydrogram MTProto):
   - Location: `bot/`
   - Entry point: `bot/bot_app.py`, handlers in `bot/handlers.py`
   - Features:
     * Batch Wizard: Ingests `.txt` indexer files containing hundreds of lecture URLs, parses trees into App -> Batch -> Subject -> Folder -> Lecture.
     * Video Stream Generator: Direct video forward/upload handler and `/stream <url>` command.
     * Interactive `/setchannel`: 1-click storage channel linking with automated permissions test and channel verification.
     * Real-time UI Cards: Live progress bar, download speed, watermark transcoding status, and storage replication updates.

C. FRONTEND CLIENT (AS Multiverse Single Page Application):
   - Location: `web/public/`
   - HTML: `web/public/index.html`
   - Styling: Vanilla CSS `web/public/index.css` (AS Multiverse Glassmorphic Dark & Light Theme)
   - JavaScript Engine: `web/public/app.js` (SPA Router, Plyr HTML5 Player, Quality Picker, Speed Controller, Study Streak Tracker)
   - Security: `web/public/security_guard.js` (Anti-screenshot DRM curtain, devtools protection, dynamic session watermark canvas)

D. MEDIA & STORAGE ENGINE:
   - Video Download: `downloader/downloader.py` (yt-dlp, direct HTTP stream fetcher with Referer/Origin headers)
   - Video Transcoding: `watermark/processor.py` (FFmpeg moving watermark, ultrafast preset, CRF 26)
   - Multi-Storage Replicator: `storage/manager.py` & `storage/providers/`
     * 1. Telegram Stream (Primary): `storage/providers/telegram_stream.py` (Unlimited Zero-Cost In-App Streaming)
     * 2. VCDN: `storage/providers/vcdn.py` (HLS H.264/AAC Adaptive Bitrate)

     * 4. AnonMP4: `storage/providers/anonmp4.py` (Direct MP4 hosting)
     * 5. Vevocloud: `storage/providers/vevocloud.py` (Ultra HD playback)


2. ZERO-COST TELEGRAM DIRECT STREAMING ENGINE
================================================================================
How Telegram video is converted into a high-speed HTTP streaming server:

A. MTPROTO CLIENT POOL (`storage/telegram_stream/client_pool.py`):
   - Manages a pool of Pyrogram clients (Primary Bot Token + Optional Worker Bot Tokens in `TELEGRAM_WORKER_TOKENS`).
   - Round-robin load balancing across worker bots for high-concurrency requests.

B. 2MB RAM LRU HEADER CACHE (`GLOBAL_HEADER_CACHE`):
   - Caches initial 2MB video headers (moov/ftyp atom boxes) in RAM during upload or first stream request.
   - Enables instant (1ms) video player startup and time seeking in Plyr / Chrome / Safari / iOS without waiting for Telegram download.

C. HTTP RFC 7233 206 PARTIAL CONTENT RANGE PROXY (`api/routes/stream.py`):
   - Handles `Range: bytes=start-end` requests from browser HTML5 `<video>` tags.
   - Streams 1MB to 4MB chunks on demand via `client.stream_media()` with offset calculation.
   - Handles client disconnects (`asyncio.CancelledError`, `GeneratorExit`, `BrokenPipeError`) gracefully.


3. SIGNATURE TELEGRAM CHANNEL POST CAPTION FORMATTER
================================================================================
File: `storage/telegram_stream/caption_formatter.py`

Every video uploaded to the Telegram Storage Channel is formatted with Course Wallah's signature blockquote template:

```html
<blockquote>——— ✦ 009 ✦——— ❞</blockquote>

<blockquote>📚 Rakesh Sir & Team. ❞</blockquote>
<blockquote>📖 SSC Pratham Batch-02 ❞</blockquote>
<blockquote>📌 Unit 4 — English — Vocab (Live ❞</blockquote>

<blockquote>📝 Topic : Vocab (Live ❞</blockquote>

<blockquote>🎬 Title : ) Class-128 | Preposition Practice ❞</blockquote>

<blockquote>├── Extention : ∮◯⚡ Course Wallah 🎓 🔥.mp4 ❞
├── Resolution : 720p (1280 × 720)</blockquote>

<blockquote>📚 Subject » Rakesh Sir & Team. ❞</blockquote>
<blockquote>📚 Course » SSC Pratham Batch-02 ❞</blockquote>

<blockquote>🌟 Extracted By : ∮◯⚡ 🅲🅾🆄🆁🆂🅴 🆆🅰🅻🅻🅰🅷 💻 ❞
∮◯🎓🔥</blockquote>
```

Formatting Rules:
- Dynamic 3-digit zero-padded index (`009`, `010`).
- HTML entity escaping (`&lt;`, `&gt;`, `&amp;`) for user inputs.
- Safe truncation to guarantee total length <= 1020 characters (fitting Telegram's 1024 character limit).
- Uploads use `parse_mode=ParseMode.HTML` in Pyrogram.

7. CRITICAL CODE GOTCHAS & RULES
================================================================================
1. NEVER fallback to YouTube if Telegram stream is active:
   - When `VideoStorage` has provider `telegram` or `telegram_stream` with status `READY`, `get_lecture_playback_access` returns `youtube_video_id: null` and `stream_url: "/api/v1/stream/tg/<msg_id>"`.
   - `tg_` prefix on video IDs (e.g. `tg_956`) is NOT a YouTube ID.

2. Pure In-App Player UX:
   - Video player in `web/public/app.js` is clean HTML5 Plyr without any bottom-right floating logos or artificial overlay banners.
   - Stream quality and speed buttons work seamlessly with the native `<video>` element.

3. Bot Document Handlers:
   - When listening for forwarded channel posts for `/setchannel`, exclude document/video/audio filters (`~filters.document & ~filters.video & ~filters.audio`) so `.txt` batch uploads are never hijacked.
